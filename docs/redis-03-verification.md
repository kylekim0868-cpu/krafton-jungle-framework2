## 설계와 검증 입력·기대 결과

- 직접 만든 해시 테이블의 각 엔트리에 값과 nullable 절대 만료 시각을 보관한다. null만 영구 저장이며 빈 값과 미스는 기존 Optional 계약을 유지한다.
- Clock=1000, TTL=10: 1009에는 적중, 1010·1011에는 미스. get이 만료 항목을 제거하고 size는 전체 만료 정리 후 유효 키 수를 반환한다.
- TTL을 주는 덮어쓰기는 새 만료를 설정하고, 생략한 덮어쓰기는 기존 만료를 제거한다.
- TTL은 양의 long 정수만 허용한다. 0/음수/소수/문자열/null/long 범위 초과/시각 합산 오버플로는 HTTP400이며 기존 값이 유지된다.
- 공통 synchronized 저장소 경계에서 get→만료 판정→delete를 보호한다. 테스트의 시계를 임계영역 안에서 latch로 멈추고 덮어쓰기와 경합시킨 후 새 값이 남음을 확인한다. sleep 기반 타이밍 테스트가 아니다.
- 8개 스레드가 2400개 키 저장·조회·덮어쓰기·일부 삭제 후 1200개 값과 크기를 확인한다. 충돌 키와 반복 확장 후 만료 정리도 검증한다.
- HTTP 고정4개 작업 스레드, 실제 HttpClient 40개 병렬 요청과 기존 경로/JSON/오류/종료 테스트 통과. TTL HTTP 테스트도 주입 시계를 사용한다.

## 제약

단일 프로세스 잠금이며 느린 저장소 작업은 직렬화된다. 백그라운드 만료 스캐너·운영 부하 제한은 없다. size는 O(버킷+키)이다. 절대 시각은 시스템 시계 변경의 영향을 받으며 성능 수치나 운영 준비 상태를 주장하지 않는다. AOF는 별도 단계다.
