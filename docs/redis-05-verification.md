- 이슈 [KJF-56](https://kylekim0868.atlassian.net/browse/KJF-56), 브랜치 `feat/KJF-56-ym-cache-benchmark`.
- 기준 `0b0fbc48481cbb4014f34b5e36509cb2e1975732`에서 생성·구현 전 최초 publish. upstream·원격 SHA 일치.
- Java25.0.5 / Maven3.9.11 `cd mini-redis && ./mvnw test`: **114개 통과, 실패·오류·생략0** (통계/HTTP 시나리오 신규5개).

## 재현

Java25 선택, Maven compile 및 runtime dependency 복사 후 mini-redis에서:

```sh
"$JAVA_HOME/bin/java" -cp 'target/classes:target/dependency/*' miniredis.benchmark.CacheBenchmark 200 500 4 5 512 3
```

인자: 모드당 워밍업200회, 측정500회, 동시4개, 테스트 원본 지연5ms, 상품 name 512 ASCII문자, 순서 회전3라운드. 캐시 서버와 상품 API는 같은 JVM의 별도 loopback HTTP 서버이며 클라이언트도 같은 JVM이다. 별도 프로세스 기능 검증과 다른 성능 실험 토폴로지다. 각 모드는 새 원본·캐시·서버·클라이언트를 사용한다.

키/데이터는 모든 모드에서 동일한 ID1~500. 같은 상품 HTTP 경로, 같은 응답 바이트(각 모드 합계265892), 같은4개 HTTP 작업 스레드, 같은4개 부하 스레드와200회 워밍업이다. HIT는 사전 적재 후 워밍업, MISS는 워밍업 후 캐시를 비우고 각 키를 정확히1회 조회한다. 준비·캐시 삭제·사전 적재는 개별 지연과 전체 측정 wall time 양쪽에서 제외한다. TTL은1시간이다. 캐시 오류0 및 측정 원본 호출 NONE/MISS500·HIT0을 검사하고 불일치 시 측정을 실패시킨다.

개별 지연은 HTTP 요청 시작부터 전체 본문 수신까지 System.nanoTime으로 수집한다. p50/p95는 nearest-rank. 처리량은500/클라이언트 측정 루프 전체 시간으로, 요청 배분·응답 검증·다음 요청 준비도 포함한다. 순수 서버 최대 처리량이 아니다. 원본 호출 수는 워밍업·준비 호출을 제외한 차이다.

## 해석·제약

이 인공5ms 원본 조건에서 적중 시 원본 호출이0이고 지연이 줄었다. 미스는 원본 조회에 캐시 GET/PUT 비용이 추가돼 항상 이득이라고 할 수 없다. 짧은 단일 호스트 실험이며 JIT/GC/OS 스케줄링·네트워크 격리·다른 장비·실제 DB·포화 부하를 통제하지 않았다. 최적 설정·운영 처리량·보편적 속도 향상으로 일반화하지 않는다. AOF의 매 쓰기 동기화 비용은 별도 실험이다.
